**日期**: 2026-05-10
**状态**: 待审核

## 一、问题分析

### 1.1 核心问题
用户反馈：academic-leap 的题目"非常简单非常幼稚，题型非常单一"

### 1.2 根因分析（基于代码审查）

通过深入分析现有代码，发现问题不在于"没有场景化能力"，而是：

**现有资产**：
- ✅ 50+ 模板，按章节组织（Chapter 16-20）
- ✅ 场景化模板已存在：`pythagoras_word_problem.ts` 包含 5 种应用场景
- ✅ 双轨制架构：模板引擎 + AI 生成引擎
- ✅ 质量机制：复杂度特征提取（cognitiveLoad, reasoningDepth, complexity）

**问题根源**：
1. **场景化模板覆盖不足**：只有勾股定理有应用题模板（1/50 = 2%）
2. **AI 提示词过于简单**：缺乏场景化指导
3. **模板扩展困难**：缺少场景化模板的扩展机制

### 1.3 参考项目研究

**kidding-study**：
- 3 种题型，流式生成
- 章节智能分块
- 模板引擎优先，AI 补充

**DeepTutor**：
- 13 种 block types
- Agent-Native 两层架构
- 双管道耦合（Problem Solving + Question Generation）

**关键借鉴**：
- ✅ 保持模板引擎优先（稳定性）
- ✅ AI 作为补充（灵活性）
- ✅ 场景化是可复制的模式

## 二、设计方案：渐进式增强

### 2.1 设计原则

**核心原则**：
1. **基于现有资产**：充分复用模板引擎和 AI 生成引擎
2. **最小侵入**：只添加新模板和优化提示词，不修改核心架构
3. **可扩展**：建立场景化模板基类后，后续扩展更容易
4. **质量可控**：模板引擎保证稳定性，AI 生成提供灵活性

**三原则审视**：
```
【三原则审视】
1. 2/8：
   - 核心20%：扩展3个知识点的场景化模板 + 优化AI提示词
   - 剩余80%：其他40+知识点后续迭代
   - 为什么不做的80%：1-2周内无法完成所有知识点，先验证模式

2. 第一性原理：
   - 根本问题：题目缺乏实际应用场景
   - 为什么这样设计：复制已验证的模式（pythagoras_word_problem），风险最低

3. 收益递减：
   - 当前方案：3个知识点 + AI提示词优化 → 覆盖率从2%提升到20%
   - 边界：20%覆盖率足以验证场景化效果，避免过度投入
```

### 2.2 架构设计

**双轨制增强**：

```
┌─────────────────────────────────────────────────────┐
│              题目生成系统（增强后）                   │
├─────────────────────────────────────────────────────┤
│                                                       │
│  轨道1：模板引擎（稳定）                              │
│  ┌──────────────────────────────────────────────┐   │
│  │ 现有：50+ 模板                                │   │
│  │ 增强：+3 场景化模板                           │   │
│  │ - Chapter 19: 一元二次方程（抛物运动）       │   │
│  │ - Chapter 18: 四边形（土地测量）             │   │
│  │ - Chapter 20: 数据分析（市场调研）           │   │
│  └──────────────────────────────────────────────┘   │
│                       ↓                              │
│  轨道2：AI 生成引擎（灵活）                          │
│  ┌──────────────────────────────────────────────┐   │
│  │ 现有：3 种题型，简单提示词                    │   │
│  │ 增强：优化提示词（场景化指导）                │   │
│  └──────────────────────────────────────────────┘   │
│                                                       │
└─────────────────────────────────────────────────────┘
```

**新增组件**：
1. **场景化模板基类**（`BaseWordProblemTemplate`）
2. **场景定义接口**（`WordScenario`）
3. **优化后的 AI 提示词**

### 2.3 实施方案

#### 阶段 1：总结应用题模板设计模式（1-2 天）

**目标**：从 `pythagoras_word_problem.ts` 提取可复用的设计模式

**输出**：`lib/question-engine/templates/base/scenario-pattern-guide.md`

**验证方法**：
```bash

# 预期：文件存在，包含场景选择、参数生成、难度分级的模式说明
```

#### 阶段 2：扩展场景化模板（1 周）

**Step 1：创建应用题模板基类**
```typescript
// lib/question-engine/templates/base/word-problem-template.ts
export interface WordScenario {
  type: string;
  weight: number;
  description: string;
  generateContext: (params: any) => string;
}

export abstract class BaseWordProblemTemplate implements QuestionTemplate {
  abstract scenarios: WordScenario[];

  generateParams(level: number) {
    // 根据难度选择场景
    // 基础：只用简单场景
    // 中等：增加中等场景
    // 高级：包含所有场景
  }
}
```

**Step 2：扩展 3 个知识点的场景化模板**

**Chapter 19：一元二次方程**
- 场景1：抛物运动（ projectile_motion ）
  - 描述：抛物轨迹计算
  - 参数：初速度、角度、重力加速度
- 场景2：面积优化（ area_optimization ）
  - 描述：矩形面积最大化问题
  - 参数：周长、宽度约束

**Chapter 18：四边形**
- 场景1：土地测量（ land_surveying ）
  - 描述：不规则地块面积计算
  - 参数：边长、角度
- 场景2：装修设计（ decoration_design ）
  - 描述：地板铺设、地毯裁剪
  - 参数：房间尺寸、材料规格

**Chapter 20：数据分析**
- 场景1：成绩统计（ grade_statistics ）
  - 描述：班级成绩分析
  - 参数：分数分布、样本数量
- 场景2：市场调研（ market_research ）
  - 描述：产品销量预测
  - 参数：历史数据、增长率

## 三、上下游依赖分析

### 3.1 影响范围

**下游（调用方）**：
- ✅ `/api/questions/generate` - 无需修改（兼容现有模板）
- ✅ `/api/questions/ai-generate` - 只需修改提示词
- ✅ `/api/assessment/start` - 无需修改

**核心引擎**：
- 📝 `/lib/question-engine/templates/` - 添加新模板
- 📝 `/lib/ai/generation/prompt-templates.ts` - 修改提示词

**上游（依赖）**：
- ✅ 模板系统 - 扩展，不修改
- ✅ 判题引擎 - 无需修改
- ✅ 渲染层 - 无需修改

### 3.2 风险控制

**零破坏性变更**：
- 所有修改都是新增，不修改现有代码
- 现有 API 保持不变
- 如果新模板有问题，可以快速回退

**向后兼容**：
- 现有模板继续工作
- 新模板通过 templateId 注册到 TEMPLATE_REGISTRY
- API 调用方无需感知变化

### 3.3 依赖扫描

**无删除操作**：本方案不涉及任何代码删除，无需依赖扫描。
